## v2.4 修了什么

| 问题 | 根因 | 修法 |
|---|---|---|
| 设备一台都扫不到 | v2.2 把探活改成「ping → TCP → isReachable」三级兜底，ping 有 2 秒超时、TCP 摸 7 个端口要 1.54 秒，单地址最坏 3.5 秒。254 台在 40 线程里跑约 22 秒，45 秒到点截断 → 只有低 IP 段有结果，手机/电视全被截断 | ① ping 确认不可用就永久降级 ② TCP 端口分批（先 3 个高效端口） ③ ARP 表已有的 IP 直接算在线 ④ 并发提到 64、超时 400ms ⑤ 超时截断时用已有结果照常渲染，没识别的补「未知设备」条目 |
| 连 5G 时信道图全空 | 只统计 2.4G 的 ch1–13 | 连 2.4G 画 13 根柱；连 5G 画四组（36-48 / 52-64 / 100-144 / 149-165），标出当前组与最空组 |
| 圆环数字看着「很少」 | 满刻度固定 100 Mbps，20 Mbps 只画 20% | 自适应刻度：<10 按 10，<50 按 50，<200 按 200，≥200 按 500；单位文字 16sp 加粗深色 |
| 只有 Mbps 没有 MB/s | — | 测速卡加 Mbps / MB/s 分段开关，选择存本地，全 App 速度显示统一换算 |
| 加密 DNS 打不开 | 用了 `android.settings.PRIVATE_DNS_SETTINGS`，很多国产 ROM 没这个页面 | 三级兜底：PRIVATE_DNS → WIRELESS_SETTINGS → 提示手动路径，不再报「打不开」 |
| 文字里有「房东」 | — | 全 App 改成中性表述，App 名改「网络体检」，报告标题改「网络体检报告」 |
| 想查哪台设备在占带宽 | Android 无 root 拿不到局域网其他设备实时流量 | 用可观测信号做「疑似占用 高/中/低」评分，并显示推断依据，不编造 Mbps 数字 |
| 没图标 | — | 雷达 + 设备点图标，全套 mipmap（48/72/96/144/192px）+ 自适应图标前景/背景层 |

## 先记住一句话

> **满格还慢 = 带宽问题；格少还慢 = 信号/信道问题。**

---

## 总分怎么算

四项各 25 分，加起来 100：

| 项 | 满分条件 | 零分条件 |
|---|---|---|
| 延迟 | 平均 ≤ 20 ms | ≥ 200 ms |
| 丢包 | 0% | ≥ 20% |
| 带宽 | 下行 ≥ 50 Mbps | ≤ 5 Mbps |
| 设备 | 没有陌生设备 | ≥ 3 台陌生 |

中间线性插值。**<50 红 / 50–75 黄 / ≥75 绿**。

## 四个页面

### 总览
头部显示 WiFi 名 · 频段 · dBm · 协商速率，下面是圆环总分 + 一句结论；2×2 白卡分别是延迟 / 丢包 / 下行带宽 / 在线设备，点任一张跳进诊断对应分段。底部「开始全面检测」一次跑完四项，带进度条和分步高亮。

### 诊断
分段控件切四项，每项一个图 + 一个结论卡 + 一个虚线折叠的原始数据。

| 分段 | 图形 | 说什么 |
|---|---|---|
| 延迟 | 信号强度时间轴 + 两条横向色带 | 卡在手机↔路由器，还是路由器↔外网 |
| 信道 | 13 根柱（2.4G）或四组柱（5G） | 该改成哪个信道 / 哪一组 |
| 带宽 | 测速圆环 + 三行对比条 | 下行 / 上行 / 耗时实测值 |
| 设备 | 统计条 + 2 列设备卡 | 谁在线、认不认识、疑似占用多少 |

### 记录
最近 30 次检测，点一条展开看当时完整报告，可清空。

### 工具
打开路由器后台 / 改加密 DNS / 关电池限制 / 打开 WiFi 设置 / 复制完整体检报告。

## 三档归因（自动判）

| 条件 | 结论 |
|---|---|
| 第一跳 `丢包>15%` 或 `平均>40ms` 或 `抖动>60ms` | 手机 ↔ 路由器这一跳不行，自己可修 |
| 第一跳正常，出网 `丢包>10%` 或 `平均>120ms` 或 `抖动>80ms` | 问题在上游线路 |
| 两段都正常 | ping 漂亮但一用就卡 = 带宽不够 |

## 设备识别靠五条判据

1. **mDNS**：`_googlecast._tcp`（Chromecast / 小米盒子）、`_airplay._tcp`、`_ipp._tcp`（打印机）、`_hap._tcp`（HomeKit）、`_miio._udp`（小米 IoT）
2. **端口**：9100/631/515→打印机；62078→iPhone/iPad；3389/445/139→Windows；554/8009/7000/5000→电视盒子；22→NAS
3. **主机名**：`iphone`/`redmi`/`macbook`/`DESKTOP-xxx` 关键词
4. **TTL**：≥250→网络设备；≥120→Windows；≥60→手机
5. **OUI 厂商表**：约 100 条常见厂商前缀

**踢人只能在路由器后台做。** 工具页点「打开路由器后台」→ 找「已连接设备 / DHCP 客户端」→ 对上 IP 或 MAC → 禁用。

> Android 10 以后系统禁止普通 App 读别人的 MAC，很多行显示读不到，路由后台能看到完整信息。

### 疑似占用带宽怎么算

普通 App 拿不到局域网内其他设备的实时流量。这里用可观测信号打分：

- 认不出来（未知设备）+2
- 开着投屏/流媒体端口（554/8009/5000/7000）+2
- 开着文件共享（445/139）+1
- 开着高流量服务端口（8080/8008/9100）+1
- TTL 像手机但认不出型号 +1

≥3 分「疑似占用高」，≥2 分「中」，其余「低」。每台设备都会显示推断依据，不给假数字。

## 测速源

按顺序自动试，哪个能通就用哪个：

1. 北外镜像 `mirrors.bfsu.edu.cn`
2. 清华 TUNA `mirrors.tuna.tsinghua.edu.cn`
3. 中科大镜像
4. Cloudflare（境外，通常最慢）

分档测速：先试 1 MB，够快（≥6 Mbps 且耗时 ≥2.5s）才加码到 8 MB，再够快才到 20 MB。太慢不加码，省流量省时间。

## 权限

| 权限 | 为什么 |
|---|---|
| `INTERNET` | 测速、读设备 HTTP 标题、ping |
| `ACCESS_NETWORK_STATE` | 读网关、DNS、频段 |
| `ACCESS_WIFI_STATE` | 扫周边 WiFi |
| `CHANGE_WIFI_MULTICAST_STATE` | 收 mDNS 应答，认设备类型 |
| `ACCESS_FINE_LOCATION` | Android 强制：扫 WiFi 列表必须给定位权限（不是用来定位你） |

## 能力边界

- **手机端能改的**：换位置、切 5G、改加密 DNS、关电池限制 —— 收益有限但免费。
- **路由器端收益最大**：改 2.4G 信道、踢陌生设备、换掉老单频路由 —— 需要后台密码（多为 `admin/admin` 或贴纸）。
- **上游带宽**：只能拿数据说话，工具页「复制完整体检报告」留档对比。
- 测速走国内镜像，比 v2.3 之前的 Cloudflare 更接近真实可用带宽。
